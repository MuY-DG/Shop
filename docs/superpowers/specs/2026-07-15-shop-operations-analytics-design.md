# Shop 运营管理与经营统计设计

日期：2026-07-15

## 目标

把现有 Art Design Pro 演示控制台替换为真实经营数据中心，并新增“运营管理”一级菜单，统一承载：

- 运营总览。
- 交易统计。
- 商品统计。
- 用户统计。
- 流量转化。
- 营销统计。
- 服务统计。

统计数据必须来自可追溯的业务事实或明确的行为采集，不使用前端硬编码、`virtual_sales`、当前成本
倒推历史毛利等不可靠数据。现有事实表可以回算的历史数据全部回算；无法回算的数据从采集启用日起
准确记录，并在页面标明采集起始时间。

## 菜单与入口

后台当前使用后端动态菜单。现有 `admin_menu.id = 100` 的 Dashboard 原位升级为“运营管理”，保留
已有角色菜单关联；`id = 101` 的 Console 升级为“运营总览”。菜单结构为：

```text
运营管理 /operations
├─ 运营总览 /operations/overview
├─ 交易统计 /operations/trade-statistics
├─ 商品统计 /operations/product-statistics
├─ 用户统计 /operations/user-statistics
├─ 流量转化 /operations/traffic-statistics
├─ 营销统计 /operations/marketing-statistics
└─ 服务统计 /operations/service-statistics
```

旧地址 `/dashboard/console` 静态跳转到 `/operations/overview`，避免历史书签失效。原
`dashboard/analysis`、`dashboard/ecommerce` 仅保留可复用的视觉实现，不作为真实菜单或数据源。

每个页面使用独立只读权限：

- `operation:overview:read`
- `operation:trade:read`
- `operation:product:read`
- `operation:user:read`
- `operation:traffic:read`
- `operation:marketing:read`
- `operation:service:read`

超级管理员默认拥有全部权限。已有控制台角色保留运营总览入口，但不会自动获得其他敏感统计页面。

## 统一统计口径

### 时间范围

- 业务时区固定为 `Asia/Shanghai`，不依赖服务器本地时区。
- 日期范围开始日包含，结束日包含；后端转换为 `[start, nextDay(end))`。
- 默认查询最近 7 个自然日，支持今日、昨日、最近 7 日、最近 30 日和自定义范围。
- 最大查询范围 366 日；粒度支持 `HOUR`、`DAY`、`WEEK`、`MONTH` 和 `AUTO`。
- 同比使用紧邻当前区间之前、长度相同的完整区间。
- 交易按 `paid_at` 计入支付日；退款按 `refund_order.success_at` 计入退款日；注册按
  `app_user.created_at` 计入注册日。

### 金额、比例与标识

- 后端金额均返回 `Long` 分，前端统一格式化为人民币元。
- 比例统一返回整数基点（`10000 = 100%`），零分母返回 `null`，不能伪造为 0%。
- 所有可能超过 JavaScript 安全整数的 ID 继续字符串化。
- 每个聚合响应包含查询区间、对比区间、统计粒度、业务时区、`generatedAt` 和可选的
  `collectionStartedAt`。
- 页面区分“真实为 0”“尚未采集”“历史不可回算”和“请求失败”。

### 经营金额

- 支付 GMV：区间内支付成功订单的 `paid_amount_cent` 之和，不因后来退款而抹掉原支付事实。
- 成功退款：区间内退款成功记录的 `refund_amount_cent` 之和。
- 净收款：支付 GMV减去同一统计区间内成功退款；它不是微信结算到账或会计利润。
- 支付订单数：区间内 `paid_at` 非空的去重订单数。
- 支付用户数：区间内支付订单的去重用户数。
- 客单价：支付 GMV除以支付用户数；平均订单金额单独使用支付 GMV除以支付订单数。
- 商品真实销量只统计已支付订单商品，不包含 `product_spu.virtual_sales`。

## 页面设计

### 运营总览

展示当前区间的支付 GMV、净收款、支付订单、支付用户、客单价、新增用户及其对比变化；展示支付、
退款、订单与用户趋势。

当前待办不受日期筛选影响，包含待付款、待发货、待审核售后、退款失败、微信发货上传失败、低库存
SKU 和待接待客服会话。已有业务页支持等价筛选的待办，以及热销商品和最近成交订单，可直接携带严格
白名单参数下钻；微信发货异常和低库存没有等价列表筛选时保持只读，不构造无效参数，商品统计页另行
展示精确库存预警明细。

### 交易统计

展示创建订单、支付订单、支付用户、支付 GMV、成功退款、净收款、优惠金额、运费、平均订单金额、
客单价和下单支付转化率。图表包含支付/退款趋势、订单状态、支付状态、退款状态、小时分布，以及
创建到支付、支付到发货、发货到完成的平均耗时。三段耗时统一以统计区间内创建的订单 cohort 为
分母基础，各阶段只对已经发生且时间顺序有效的样本求平均。

支付渠道真实成功率从新增的支付尝试事实计算；采集启用前只展示“历史不可回算”。

### 商品统计

展示 SPU/SKU 总量和状态、当前库存、缺货与低库存；展示商品及分类的支付件数、支付商品毛额、
支付用户、订单数、净销量、退款率和排行。

商品毛利使用下单时成本、优惠分摊和实付分摊快照。旧订单缺少成本快照时，不使用当前 SKU 成本
冒充历史成本；页面返回可计算覆盖率，并标明统计起始点。

### 用户统计

展示累计用户、新增用户、活跃用户、支付用户、新增支付用户、首购用户、复购用户、复购率和手机号
授权率。图表包含注册、活跃和支付用户趋势，购买次数分层、用户价值排行和注册 cohort 留存。

活跃与留存以服务端日活事实为准，不使用单个 `last_login_at` 反推历史。注册 cohort 展示 D1、D7、
D30 留存，区分未成熟、采集前不可回算和成熟后的真实 0。

手机号授权新增首次授权时间 `phone_authorized_at`。迁移时把已有授权状态建立为采集启用时快照，此后只
记录首次授权时间；采集前的历史区间不返回伪造的授权人数或同比。

### 流量转化

展示 PV、UV、会话、登录活跃用户、入口场景、热门页面、热门搜索词，以及首页访问、商品详情、
加购、开始结算、提交订单、支付成功的去重用户漏斗。流量指标明确显示采集起始时间。

客户端只上报页面和交互行为；订单、支付和退款仍以服务端业务事实为准。漏斗通过持久化的访客、
会话及订单归因字段关联，不相信客户端传入的用户 ID 或支付结果。

### 营销统计

展示优惠券领取/后台发放量、使用量、过期量、使用率、优惠金额、券支付订单金额、发放来源分布和
优惠券模板排行。活动场景与来源从受控的入口场景字段统计；没有投放成本事实时不展示伪造 ROI。

### 服务统计

展示待发货、超时未发货、平均发货/完成耗时、物流公司分布和微信发货上传结果；展示售后申请、
通过/拒绝、退款成功/失败、退款率、退款原因和处理耗时；展示客服会话量、等待量、首响、解决耗时、
关闭率、转接率和坐席负载。

## 缺失数据补全

### 行为事件

新增 `analytics_event`，记录受控事件类型、匿名访客、会话、已认证用户、页面、商品、订单、入口
场景和发生时间。客户端事件使用 UUID `client_event_id` 幂等去重，批次最多 50 条；不保存 OpenID、
UnionID、原始手机号、IP 或任意无限制 JSON。

新增 `POST /app/analytics/events/batch`：

- 允许匿名访问；有合法 App Token 时由服务端关联用户。
- 只接受允许列表中的客户端事件：`APP_LAUNCH`、`PAGE_VIEW`、`PRODUCT_VIEW`、`SEARCH`、
  `CHECKOUT_START`。
- 事件时间必须在合理时钟偏差内，字符串长度、批次大小和商品引用都受校验。
- `CART_ADD`、`ORDER_SUBMIT`、`PAYMENT_SUCCESS` 等可信业务事件由服务端记录或从事实表读取，
  不接受客户端伪造。
- 商品/SKU 引用必须对应当前可售数据；匿名接口按可信代理解析后的客户端 IP 与访客 ID 双维度使用
  Redis 原子限流，限流器故障时记录告警但不阻断购物主流程。

小程序生成持久匿名访客 ID、单次启动会话 ID和入口场景，并在关键页面与操作批量上报。商品列表补齐
真实搜索入口，提交非空搜索词后才记录搜索事件。上报失败不阻断购物流程，重复提交由服务端幂等
处理；确定性的坏事件通过批次二分隔离，不能堵塞同访客的后续合法事件。

原始行为事件默认保留 400 天，以覆盖最长 366 天报表区间，并按上海业务日期定时、分批清理；保留期
和批次上限均可配置，清理失败不影响业务请求。

### 用户日活

新增 `app_user_daily_activity`。所有已认证 `/app/**` 业务请求按上海自然日幂等 upsert 用户首次、
末次活跃时间和请求数，为 DAU、WAU、MAU 与留存提供服务端事实。

### 订单商品经营快照

`order_item` 新增可空历史兼容字段：

- `unit_cost_cent`
- `line_cost_cent`
- `coupon_discount_allocated_cent`
- `freight_allocated_cent`
- `paid_amount_allocated_cent`

新订单按稳定余数分配规则分摊优惠、运费和实付金额，保证行级合计严格等于订单级金额。成本在创建
订单商品时从锁定 SKU 快照；成本缺失则保持 `null`，不能按 0 成本计算毛利。

### 支付尝试和库存预警

新增 `payment_attempt`，在调用支付提供方前落库，记录发起、预下单成功、失败、支付成功和关闭状态，
用于真实支付成功率与失败原因统计。

`product_sku` 新增 `low_stock_threshold`，默认 10，并纳入商品编辑请求、响应和校验；库存不高于阈值
且 SKU/商品可售时计为低库存。

### 退款商品与结算边界

当前业务只允许整单全额退款，第一版可按订单商品归属退款件数。新增统计实现必须隔离这一假设；未来
支持部分退款时，应先增加 `after_sale_item` 和 `refund_item`，再开放商品级部分退款指标。

微信手续费、结算日和真实到账当前没有事实来源，不在本阶段伪造。后续以微信账单导入/对账模块补充。

## 后端接口

新增独立 `org.muybaby.shopserver.operation` 模块：

- `GET /admin/operations/overview`
- `GET /admin/operations/trade-statistics`
- `GET /admin/operations/product-statistics`
- `GET /admin/operations/user-statistics`
- `GET /admin/operations/traffic-statistics`
- `GET /admin/operations/marketing-statistics`
- `GET /admin/operations/service-statistics`

每页使用一次聚合快照请求，排行数量受限；需要大量明细时跳转现有分页列表。后端统一计算公式、比较
值和空值语义，前端不得从多个分页接口自行汇总。

第一版从带索引的事实表实时聚合；行为事件增长后再引入 `stats_daily_shop`、`stats_daily_product`、
`stats_daily_user` 日汇总，不在本阶段提前建设数据仓库。

## 管理后台

新增运营 API、类型、日期工具栏、指标卡、采集状态、趋势图、分布图、排行表和待办组件。复用 ECharts
与现有卡片视觉，但修正“所有值为 0 等同暂无数据”的逻辑，并为金额、比例、真实零、不可用和历史
不可回算提供独立展示。

所有指标提供口径说明和生成时间；权限不足的页面不出现在菜单中，后端仍以 `@PreAuthorize` 保护。

## 验证原则

- 先写迁移、口径和控制器失败测试，再实现查询。
- 日期边界固定使用上海时区并测试跨日、月、年边界。
- 覆盖退款发生日与原支付日分离、零分母、旧订单成本不可用、虚拟销量排除、事件幂等、匿名事件、
  伪造用户/支付事件拒绝、超大 ID 字符串化和权限 403。
- H2 聚合测试之外，运行 MySQL 8 迁移兼容测试。
- 后台运行类型检查、构建、精确 ESLint/Stylelint；小程序运行单元测试和类型检查。

## 暂不包含

- 微信账单导入、渠道手续费、会计结算和财务对账。
- 部分商品退款与退货入库。
- 广告投放成本、跨渠道归因和自动化营销编排。
- 独立数据仓库、离线 ETL 或无限期保存原始行为事件。

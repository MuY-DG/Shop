# 微信 2001 购物（实体物流）服务动态设计（V94A）

## 目标与边界

本阶段只实现微信新版 `notify_type=2001` 的“购物（实体物流）服务动态”。不接入传统订阅消息，不修改管理后台页面或小程序代码，不把服务动态是否可用作为支付、发货、签收或售后的前置条件。

微信后台添加模板后得到的账号模板记录 ID 仅作为开通就绪度和审计信息保存。调用 `set_user_notify` 时只发送 `openid`、`notify_type`、`notify_code`、`content_json` 和激活时的 `check_json`，绝不发送模板记录 ID（包括 `priTmplId`）。

意图采集开关、Worker 外呼开关和结果回调开关分别默认关闭。可以先只开启意图采集完成队列验收，再独立开启 set/get 外呼；未配置回调 Token 或 EncodingAESKey 不影响服务动态投递和主动对账。

## 官方契约冻结

- `notify_type` 固定为 `2001`，`notify_code` 固定使用本小程序微信支付交易单号。
- 激活必须在支付后 24 小时内完成；激活后可更新 30 天。
- 本系统第一次写入固定使用状态 2“待发货”，并携带支付金额和支付时间校验信息。
- 激活内容的 `product_count` 是全订单快照商品数量总和；`product_list.info_list` 按订单项顺序最多披露前 10 项，避免把展示列表上限误当成订单总件数。
- 状态映射：待发货 2、已发货 4、已签收 6、售后中 7、售后结束 9、交易取消 10。
- 当前订单在 `COMPLETED` 后仍允许申请售后，系统也没有“售后期真正结束”的业务事件。因此本阶段不自动写状态 8“交易成功”，避免状态 8 终态阻断后续合法的 7“售后中”。
- 状态 11“售后关闭”也是终态，本阶段不用于仍可继续交易或再次售后的订单。
- 除状态 3 外，禁止向同一状态重复更新。本项目当前单包裹发货，不产生状态 3。
- 合法前态严格采用官方 2001 状态机；8、9、10、11 为终态。

## 售后恢复语义

进入状态 7 前保存最后一个非售后状态。部分退款、售后取消、驳回或退货关闭但订单继续履约时，恢复此前的 2、4 或 6，而不是发送终态 9/11。只有整单全额退款完成时才按 `7 -> 9` 结束服务动态。若全额退款事件到达时尚未排入 7，则同一事务按序排入 7 和 9。

## 可靠性与事务边界

- 订单状态日志写入所在事务只创建服务动态卡片和不可变投递记录，不发 HTTP。
- Worker 每张卡只认领最早未结束的序号，避免后态越过前态。
- HTTP 请求在数据库事务之外执行；成功、失败、未知结果在独立短事务中落库。
- 网络断开、响应无法解析或 `85448` 进入 `UNKNOWN`，先调用 `get_user_notify` 对账，不盲目重发。
- 对账发现远端已到目标状态即确认成功；仍在合法前态时至少两次间隔观测后才允许低频重试，不因本地次数阈值伪造终态失败；远端超前时收敛已被覆盖的本地序号，不发送倒退或重复状态。
- `85431`、`85448`、`85449` 和传输结果不明一律先进入未知并主动查询；`85437` 先查询确认尚未激活后至少退避一分钟。参数、状态机、权限、安全拦截、过期类错误终止自动重试。
- 超时的 `SENDING` 先转为 `UNKNOWN`，不得直接按失败重发。

## 数据和隐私

V94 创建卡片、投递、回调审计三张表。OpenID 和微信支付交易号仍以现有支付表为事实来源，服务动态表只保存交易号摘要用于回调匹配。管理接口不返回 OpenID、交易号、Token、AESKey 或模板 ID 原文。

每次外呼前，从支付订单引用的不可变 `payment_config.app_id` 或 ENV 指纹对应的 `payment_config_snapshot.app_id` 读取支付 AppID，并要求与当前小程序 AppID 完全一致；不为这项身份校验解密 APIv3、PEM 或读取 COS 密钥文件。

## 结果回调

回调只处理 SAFE + JSON 模式的 `notify_service_msg_send_result`。校验 `msg_signature`，使用 AES-CBC 解密并校验明文 AppID；不接受明文模式。请求包含时间窗口校验、摘要幂等和数据库唯一约束。回调匹配同时兼容官方示例中严格的 `p1.` 加纯数字交易号前缀，但 set/get 始终继续使用原微信支付交易号。一般异步失败只记录诊断，绝不回滚已确认的远端状态或重复发送同一状态；`-1004` 与主动查询得到的 `code_state=10` 会仅封禁当前订单卡片，并把尚未结束的后续意图安全标为跳过，其他订单和用户全局状态不受影响。`-1003` 仅表示消息模板展示失败，不封禁卡片。

账号级消息推送 URL 固定为 `/wechat/mini/message`。本阶段通用入口只把已验签、已解密的 2001 消息投递失败事件交给服务动态处理器；未来新增客服等账号消息时复用该入口，不再迁移微信后台 URL。

## 运维面

后端提供只读状态和投递分页接口，复用 `order:read` 权限。状态接口展示总开关、核心配置就绪度、回调是否独立就绪以及积压/未知/失败数量；不提供后台人工强推，以免绕过官方状态机。

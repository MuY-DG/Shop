# Shop 在线客服草稿激活实施计划

日期：2026-07-15

## 行为目标

- 用户仅打开客服页时创建或更新 `DRAFT` 会话，保存默认商品/订单，但不进入后台队列、不增加未读、不发送实时通知。
- 用户首次发送文字、图片、订单卡片或商品卡片时，原子地将会话转为 `WAITING`。
- 激活时先写入默认咨询对象卡片，再写入用户主动发送的内容，因此客服认领后仍能立即看到入口上下文。
- 已处于 `WAITING` 或 `ACTIVE` 的会话继续沿用当前轮次；`CLOSED` 会话再次打开时只建立下一轮草稿，首次发送后才真正重开。
- 后台列表和直接读取接口都隐藏草稿会话。

## 实施切片

1. 新增 V25，为会话增加当前轮次的 `activated_at`，已有非草稿会话补齐激活时间。
2. 先扩展控制器和迁移测试，覆盖打开不排队、草稿上下文替换、首次发送激活、关闭后草稿重开、后台不可见。
3. 重构客服服务：草稿上下文只写资源，不写消息；首次主动发送负责激活并补写默认卡片。
4. 小程序增加草稿状态和“发送消息后客服接入”文案；后台类型兼容草稿但不提供草稿筛选。
5. 运行后端全量测试、后台构建、小程序测试/类型检查与 `git diff --check`。

## 不改变的边界

- 不改变订单所有权、在售商品校验和图片私有访问。
- 不把页面停留时长当作自动排队条件。
- 不向客服角色增加退款、发货、关闭订单等写权限。

# Shop 小程序用户名称功能实施计划

日期：2026-07-15

## 目标

为小程序用户补充可编辑的用户名称（领域字段使用 `nickname`），并在订单、售后后台中提供名称展示与模糊搜索，保持用户名称与收货人姓名、后台管理员用户名相互独立。

## 当前基线

- `app_user` 只有微信标识、手机号、状态和登录时间，没有用户名称。
- `/app/users/me` 只返回用户 ID、脱敏 OpenID 和脱敏手机号。
- 小程序个人中心没有资料编辑能力。
- 管理端订单、售后只支持按用户 ID、手机号搜索，列表未展示小程序用户名称。
- 工作区已有“整单退款期间暂停履约”等未提交改动，并且与订单、售后文件重叠；本计划只做增量合并，不回退或覆盖这些改动。

## 设计决策

1. 数据库字段命名为 `app_user.nickname`，接口和小程序资料使用 `nickname`，管理端 DTO 使用 `userNickname`。
2. 名称不是登录凭证，也不要求唯一；微信 OpenID 仍是小程序身份依据。
3. 名称保存前去除首尾空白，长度限制为 2～32 个字符，拒绝控制字符。
4. V22 为已有用户回填 `用户` + 用户 ID 后六位；新用户注册时按同一规则生成默认名称。
5. 历史订单不保存用户名称快照，后台始终展示账号当前名称；收货人仍使用订单地址快照。
6. 订单、售后名称搜索采用包含匹配；手机号继续只作为搜索条件或详情字段，不恢复到列表中。
7. 现有“系统管理 → 用户管理”仍只管理后台管理员，本阶段不新增小程序会员管理菜单。

## 实施步骤

### 1. 数据库与后端用户资料

- 新增 V22 迁移，为 `app_user` 添加并回填 `nickname`。
- 扩展 `AppUser`、`AppUserService`、`AppUserProfile` 和资料映射。
- 新增 `PUT /app/users/me`，接收并校验昵称后返回最新资料。
- 补充迁移、服务与控制器测试，覆盖默认名称、更新、越权/未登录、空白、长度及控制字符。

### 2. 订单与售后后台接口

- 查询条件增加 `USER_NAME`。
- 订单列表/详情和售后列表/详情返回 `userNickname`。
- 使用 `app_user.nickname LIKE` 做模糊搜索，并保证状态数量接口沿用相同条件。
- 扩展控制器测试，验证名称搜索和响应字段。

### 3. 管理端页面

- 订单、售后搜索下拉增加“用户名称”。
- 订单、售后列表增加用户名称展示，同时保持收货人列语义不变。
- 详情用户信息增加用户名称。
- 更新 API 类型并运行格式、类型检查和构建。

### 4. 小程序个人中心

- 扩展 `AppUserProfile` 类型、会话序列化与恢复逻辑。
- 新增更新用户名称的服务方法。
- 个人中心展示用户名称，并提供编辑、保存、取消及错误提示。
- 补充页面与会话测试，确保旧缓存资料缺少 `nickname` 时仍可恢复并由服务端刷新。

### 5. 验证

- 后端聚焦测试：用户资料、认证、订单管理、售后管理、V22 迁移。
- 后端全量 `./mvnw test`。
- 管理端 `pnpm typecheck`、相关 ESLint、`pnpm build`。
- 小程序 TypeScript/测试门禁。
- `git diff --check`，确认未覆盖现有未提交退款流程改动。

# Shop 在线客服与实时通知第一版实施计划

日期：2026-07-15

设计依据：`docs/superpowers/specs/2026-07-15-shop-customer-service-realtime-design.md`

## 工作区边界

执行前仓库位于 `main`，且已有未提交的订单、售后、小程序昵称等改动。本阶段：

- 不回滚、不重排、不格式化无关文件。
- 新增客服模块文件，尽量避免触碰已有脏文件。
- 必须修改的共享文件仅做最小增量：后端 `pom.xml`、安全配置、支付完成事件、小程序 `app.json` 与资料页入口、后台 Vite WebSocket 代理、订单页实时订阅。
- 后台客服类型使用独立 `customer-service.d.ts`，不在已有脏的 `api.d.ts` 中扩写。

## Slice 1：数据库和权限

1. 新增 V23 迁移，创建会话、消息、分配日志和订单关联表。
2. 新增客服权限、菜单和 `R_CUSTOMER_SERVICE` 角色。
3. 为超级管理员和客服角色授予菜单/权限。
4. 增加 H2 迁移结构测试，覆盖唯一约束、索引、菜单和授权。

## Slice 2：后端客服服务和 REST API

1. 先写控制器集成测试：用户开会话/发消息/关联自己的订单；管理员列表/认领/回复/转接/关闭。
2. 覆盖越权订单关联、非负责人回复、重复认领、幂等消息和关闭后重开。
3. 实现 DTO、`CustomerServiceService`、App/Admin Controller。
4. 实现候选订单查询和启用客服列表。

## Slice 3：实时基础设施与订单提醒

1. 加入 Spring WebSocket starter。
2. 实现一次性短期票据、握手拦截器、连接注册表和 JSON 事件信封。
3. 为客服事务增加提交后事件。
4. 在支付 `finalizePaid` 的首次成功分支发布提交后 `ORDER_PAID` 事件；重复回调不发布。
5. 增加票据一次性、过期测试，并用客服生命周期集成测试验证事件触发点依赖的事务写入。

## Slice 4：管理后台客服工作台

1. 新增客服 API、独立类型声明和统一 `RealtimeClient`。
2. 新增 `/customer-service` 页面：状态筛选、会话队列、聊天记录、发送、认领、转接、结束和订单关联。
3. 实时事件触发合并刷新，断线后 15 秒轮询。
4. 通过后台类型检查和生产构建验证会话状态、操作判定与实时事件去重逻辑。

## Slice 5：后台订单实时提醒

1. 建立管理员单例实时客户端，由当前业务页面订阅，避免同一页面重复建连接。
2. 将事件分发给订单页和客服页。
3. 订单页收到 `ORDER_PAID` 后弹出通知，并更新状态计数与列表。

## Slice 6：小程序客服页

1. 新增客服 service、类型和页面路由。
2. 在“我的”增加“在线客服”入口；从订单详情增加“咨询此订单”入口。
3. 页面支持历史消息、发送文字、订单关联状态、等待/接待/结束状态。
4. 页面内使用实时连接，失败时 5 秒轮询。
5. 增加实时地址转换和入口测试，并运行小程序完整类型检查。

## Slice 7：验证和审查

1. 后端目标测试，再运行 `./mvnw test`。
2. 后台运行 `pnpm typecheck` 和 `pnpm build`。
3. 小程序运行 `pnpm test:typecheck`、`pnpm test` 和 `pnpm typecheck`。
4. 运行 `git diff --check`，审查权限边界、事务提交后事件、消息幂等、WebSocket Token 泄露和现有脏改动重叠。
5. 修复后重跑受影响测试，输出尚需用户执行的真实微信开发者工具 smoke。

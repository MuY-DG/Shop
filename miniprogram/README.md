# 灶香集微信小程序

`miniprogram` 是基于现有 Spring Boot 后端重新搭建的原生微信小程序，业务数据以当前后端接口为准。

## 当前阶段：生产就绪收口（V85-V90）

- TypeScript + Less 严格模式与 pnpm 工具链
- 集中式颜色、排版、间距、圆角、阴影设计令牌
- 自定义导航、按钮、卡片、标签、加载/空/错状态组件
- 环境配置、结构化 `ApiError`、JSON 请求层
- 用户主动微信登录、已注册用户免重复手机号授权、刷新令牌 single-flight 与 HTTP 401 最多恢复一次
- 公开 `GET /app/home` schema v3 接入（Redis 缓存静态内容，可售状态由后端实时覆盖）
- 真实轮播、分类、`HOT/FEATURED` 与 `RECOMMENDED/COMPACT` 商品区块
- 首屏骨架、空状态、失败重试、下拉刷新与图片缺失降级
- 首页业务路径白名单，不执行外部链接
- 分类商品列表、关键词搜索、分页加载、销量与可售状态
- 商品详情图片、参数、SKU、可售状态、数量和批发阶梯价联动
- 首页轮播、分类和商品卡片已打通列表/详情浏览路径
- 自定义底部导航：首页、分类、购物车、我的
- 分类 Tab 与分类列表页复用同一商品目录业务组件
- 首页拆分轮播、分类宫格和商品区块，详情拆分画廊、摘要、参数、SKU、批发价和数量组件
- 真实购物车列表、商品勾选、数量调整、失效状态、批发价、移除和清空
- 购物车 `CART` 与商品详情 `DIRECT` 共用安全结算参数和订单预览页
- 账户收货地址选择、微信地址导入、服务端最优优惠券与运费实时预览
- 幂等订单提交与支付成功页；购物车订单创建后由后端清理选中项
- 微信 JSAPI 支付参数获取、`wx.requestPayment` 拉起与服务端支付结果同步
- 确认订单页原位切换等待支付、服务端时限倒计时、继续支付与安全取消
- 已取消、已收货订单支持软删除；待收货、待评价、已完成和已取消订单可按当前库存、价格重新购买
- 订单中心支持商品快照主图、规格、单价与数量，并提供待评价、已完成、已取消等状态分组
- 已完成始终表示已收货；待评价是已收货订单中仍有当前可评价商品尚未评价的派生子集
- 待付款订单支持修改收货地址，订单商品、库存、优惠与支付金额保持不变
- 订单中心提供独立文字评价页，复用真实星级、内容与匿名评价能力
- 个人中心订单入口与待付款、待发货、待收货、待评价快捷入口
- 收货地址列表、新增编辑、默认地址与安全删除
- 微信原生地图选址和收货地址回填
- 领券中心、我的优惠券与待使用/已使用/已过期状态筛选
- 收藏商品与足迹列表、分页、批量删除和足迹清空
- 个人中心微信原生在线客服入口
- 订单详情售后入口、整单全额仅退款申请与重复申请拦截
- 头像、售后凭证与客服图片通过业务 API 申请一次性表单后直传 COS，业务服务器不转发图片字节
- 订单私有售后凭证选择、大小校验、COS 数据万象 WebP 处理与提交绑定
- 客服图片保留发送方本地即时预览，接收方优先下载 COS 签名缩略图并使用 7 天有界磁盘缓存
- 客服聊天保留跨咨询轮次的连续时间线，首次加载最近 50 条并按游标向前分页
- 售后记录分页、六状态进度详情、审核说明与退款结果查询
- `develop`、`trial`、`release` 运行环境显式解析，正式版生产 API 缺失或指向开发地址时 fail closed
- 登录页通过 `wx.getPrivacySetting` 展示微信小程序平台配置的隐私保护指引名称；未勾选不调用 `wx.login`，勾选后才预加载，点击“微信一键登录”后提交会话
- “关于与协议”的隐私入口使用微信原生只读指引；商家资质、用户协议和售后服务政策继续展示后台当前发布版本
- 食品商品详情在自由图文之前展示结构化食品信息与真实标签图片，未分类和非食品商品不伪装为食品披露
- “账户注销与个人信息权利”支持申请、查询和待处理撤回；注销只在用户确认后获取新的微信登录 code
- 微信发货未成功上传时按真实状态提供本地收货路径，`UPLOADING/UNKNOWN` 等歧义态不伪装成已完成
- 个人中心 V 头像框、皇冠、`金牌会员` 文案、会员卡素材和登录展示条件保持不变，合规入口位于会员卡之外

## 目录约定

```text
miniprogram/
  custom-tab-bar/ 微信四入口自定义底部导航
  components/   可复用的通用 UI 与业务组件
  config/       环境和运行时配置
  constants/    API 路径等稳定常量
  features/     后端 DTO 到页面 view-model 的纯映射
  pages/        页面，只负责展示与交互编排
  services/     会话与按业务域组织的接口
  styles/       tokens、mixins 等设计基础
  types/        与后端 DTO 对齐的 TypeScript 契约
  utils/        HTTP、错误和系统能力适配
```

页面不能直接调用 `wx.request`，也不要在业务 Less 中重复定义已有语义色；分别通过 `utils/request.ts` 和 `styles/tokens.less` 使用统一能力。页面只负责任务编排与路由，组件边界和维护规则见 `miniprogram/components/README.md`。

## 本地检查

```bash
pnpm install --frozen-lockfile
pnpm check
```

`check` 会依次执行生产代码类型检查、测试代码类型检查，以及主动登录/手机号按需授权、会话并发/401 恢复、首页契约映射、购物车选择、CART/DIRECT 结算参数、售后状态与凭证上传、价格和安全路径等测试。V85-V90 还覆盖环境 fail-closed、隐私同意顺序、客服订单路由、公开合规页、食品披露、账户权利以及 `金牌会员` 展示不变量。

微信开发者工具导入当前目录即可预览。运行环境由微信
`envVersion` 决定，配置入口为 `miniprogram/config/app-config.ts`：

- `develop` 指向现有开发 API，并使用开发会话命名空间；
- `trial` 当前显式复用开发 API，但使用独立会话命名空间，因此只能作为连接开发后端的体验版，不能作为独立预发布或生产验收；
- `release` 使用独立生产会话命名空间，仓库内 API 值故意保持为空；在商家确认真实生产 HTTPS 域名前，正式版会启动失败且不会回退到开发 API。

不要把示例域名、开发域名或临时隧道当作生产配置。正式版会拒绝空值、非
HTTPS、无效主机、localhost/loopback 和包含 `pay-dev` 的开发主机。替换
`RELEASE_API_BASE_URL` 前，先确认网关路由、证书、回调地址及微信公众平台合法域名一致。

当前以 WebView 和基础库 2.32.3 为兼容基线。正式版启动时会拒绝 `development` 配置；发布前必须设置生产环境与 HTTPS API，并在微信公众平台分别配置：

- request 合法域名：业务 API 域名
- uploadFile 合法域名：对象存储配置中的 HTTPS COS 客户端域名；另保留 COS
  默认源站和业务 API 域名供旧版本兼容与回滚
- downloadFile 合法域名：同一个 COS 客户端域名、历史对象或回滚使用的默认
  COS 源站，以及
  `https://thirdwx.qlogo.cn`、`https://wx.qlogo.cn` 和 `https://mmbiz.qpic.cn`

当前存储桶的图片上传、公开图片和私有图片签名下载统一直接访问配置的 COS
源站，当前方案不使用 CDN。自定义源站域名直接 CNAME 到 COS，也不属于 CDN。
正式环境请将上述业务域名和 COS 域名替换为实际生产配置。切换域名前先增加
微信合法域名并发布能动态接受后端签发的合法 HTTPS 根域名的客户端，再切换
后台对象存储配置。

## 发布前真实门禁

小程序页面和自动化检查不能替代真实商家数据与微信环境。发布前必须完成：

- 在微信小程序平台维护与实际能力一致的隐私保护指引，并在后台发布经审核的真实商家主体/证照、用户协议和售后服务政策；后台隐私政策可独立保留，但不作为小程序登录数据源；
- 对全部在售商品人工确认 `FOOD` / `NON_FOOD`，清零历史 `ON_SALE + UNCLASSIFIED`；食品必须使用真实包装标签、结构化事实和 SKU 净含量；
- 为账户权利申请指定实际负责人、时限、升级路径和保留规则，不把测试说明当成正式处理结论；
- 用真实专用测试账号完成登录、支付、发货上传/对账、收货、退款、COS、地图地址、客服、官方物流插件与真机回归；
- 核对上传包清单和主包体积后再在微信开发者工具执行体验版/正式版上传。

完整门禁、数据库迁移与回滚步骤见
[`docs/production-release-checklist.md`](../docs/production-release-checklist.md)。
